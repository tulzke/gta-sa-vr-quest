# Ручная служебная рация — задача 97

Выбран вариант 1 с верхней окрашиваемой накладкой. Модель и хват утверждены пользователем; реализация игровой фичи разрешена.
Пользователь явно разрешил коммитить ассеты через LFS и попросил убрать README
из папки модели; описание перенесено сюда.

- `assets/service-radio/service-radio-v1.blend` — редактируемый исходник Blender 4.5 LTS.
- `assets/service-radio/service-radio-v1.glb` — обменный экспорт самой рации и держателя.
- `manifest.json` — размеры, состав, цвета и матрицы посадки в кисти.
- `assets/vrhands/source/Hands.blend` — существующий исходник рук с добавленным
  Action `HandleRadio`. Остальные 14 Actions, меш, веса и rest-риг сохраняются.

Радио — отдельный предмет, без провода и автомобильного базового блока.
Единицы — метры; X вправо, −Y лицевая сторона/динамик, Z вверх. Корпус
около 5,6 × 3,4 × 14,2 см, верхняя накладка шириной 6 см;
с жёсткой антенной общая высота около 21,2 см.
`RadioBody` содержит переносимую рацию, `RadioCradle` — неподвижный держатель.
Студийная коллекция исключена из GLB.

`ServiceAccentCollar` — единственная деталь с материалом `RadioServiceAccent`.
Меняется только её цвет: синий для полиции, белый для медиков, красный для
пожарных. Отдельные модели/текстуры для служб не нужны. Точные runtime-значения
и доступность моделей транспорта будут подключены после согласования ассета.

`RadioPTT` — отдельная боковая кнопка с ходом 1,5 мм по локальной +X.
Action `RadioPTTPress`: кадр 1 — отпущена, 11 — нажата. `IndexPressAnchor`
обозначает контакт указательного, `DockAnchor` — посадку в держателе.

`HandleRadio` использует существующий риг правой кисти: указательный на PTT,
большой направлен вверх вдоль противоположной грани, остальные три пальца
обхватывают корпус. Кадры 1…11 — от удержания до небольшого нажатия указательным;
остальные пальцы неподвижны. Action помечен fake user и Asset для поиска в Blender.
Поза левой кисти получается отражением существующей общей геометрии рук.
При этом сама рация поворачивается в другую сторону, а не отражается: боковая
кнопка остаётся под указательным. Матрицы для обеих рук записаны в manifest
и пустых объектах `HandWristAnchor_Right/Left` в системе рации. Координаты
исходного рига рук — сантиметры; матрицы посадки — канонические метры кисти,
без исходного размещения сцены.

Рендеры и сцена примерки находятся в `build/service-radio/`, исходный снимок
рук до изменения — в `.cache/service-radio/`. `tools/build_service_radio.py`
пересоздаёт собственные `.blend`/GLB и рендеры; не запускать поверх ручных
изменений модели. `tools/prepare_radio_hand_pose.py` создаёт рабочую копию
рук в `.cache`, проверяя неизменность существующих Actions/рига/меша;
не перезаписывает исходник рук. `tools/verify_service_radio_blender.py`
повторно открывает рабочую копию, проверяет Action, замкнутость деталей,
выделенный материал, ход кнопки и обратный импорт GLB.

## Игровое подключение

`runtime/service-radio.mesh` встроен в native-библиотеку. Один статический
VBO/EBO содержит 4187 вершин и 8210 треугольников: роли 0 — держатель,
1 — корпус, 2 — цвет службы, 3 — кнопка. Отдельных текстур нет. При захвате
рация следует той же опубликованной позе кисти, что и HandRenderFrame;
матрица корпуса имеет положительный определитель для обеих рук. Возврат
после отпускания занимает 180 мс, команды при возврате не создаются.

`HandleRadio` включён в библиотеку из 15 клипов, экспортёр и runtime enum.
Прогресс 0…1 двигает указательный к кнопке. Старые 14 конечных поз совпадают
с предыдущим GLB точно. `tools/export_hand_glb.py` сохраняет source hash
актуального `Hands.blend`; hand GLB также хранится через LFS.

Иммерсивное управление водителем: новый grip возле рации — захват;
после отпущенного триггера новое нажатие запускает либо отменяет штатное
служебное задание. Удержание не повторяет команду. Триггер занятой руки
исключён из газа/тормоза, стрельбы, телефонного и общего ввода; после возврата
с зажатым триггером педаль остаётся заблокированной до отпускания.
Другая рука сохраняет управление. Хват блокирует захват оружия и двери.

Начальная область: скорая 416, пожарная 407, наземный полицейский транспорт
427/432/490/523/528/596/597/598/599/601. Прочие типы транспорта, такси и
телефон сутенёра этой итерацией не добавлены. Класс автомобиля определяет
только показ устройства и цвет: окончательные условия запуска проверяет игра.
Внешняя камера, пассажир, редактор, меню, катсцена, потеря трекинга/смена его
эпохи и выход/смена машины сбрасывают взаимодействие.

Место держателя хранится отдельно для модели в `ServiceRadioPose.<model>.<field>`
(12 значений: центр и три локальных оси). В Vehicle Debug триггером возле
рации можно перемещать и поворачивать узел; отпускание сохраняет профиль.
Расчёт позиции общий для показа, захвата и редактора. Сброс общего пресета
транспорта также сбрасывает позу рации. Начальные позиции требуют примерки
в конкретных кабинах Quest.

## Штатные скрипты Android 2.11.311

В локальном `mainv1.scm` общий автомобильный диспетчер у 83672 проверяет
`$0x660`, тип машины, мини-игру, воду и флаг `$0x614` перед опросом команды.
Медик: model 416 / widget 70 у 84214 / launch 122 у 84372;
пожарный: model 407 / widget 70 у 84473 / launch 123 у 84631;
полицейский: штатный police predicate / widget 70 у 84719 /
launch 124 у 84984. Адаптер не вызывает launch и не меняет globals.

Отмена опрашивает widget 72 в служебных миссиях `AMBULAN`, `FIRETRU`,
`COPCAR`. Например, COPCAR у 2983872 использует свой двухфазный latch:
первый опрос ставит local 0x46=1, следующий делает WAIT 100 и ставит 2.
Поэтому одно физическое нажатие даёт ограниченный импульс 120 мс;
повторные опросы внутри него не потребляют запрос. Штатный скрипт выполняет
очистку и отмену. Запрос ожидает подходящий опрос не более 250 мс, затем
отбрасывается. Он привязан к SeatKey с поколением vehicle pool и типу/экземпляру
служебной миссии. Чужая сюжетная миссия не получает отмену. Переход запуска
в отмену при смене состояния не допускается. Совместимость проверяется
по четырём инструкциям диспетчера; при несовпадении мост отключается.

## Проверки

- `tools/test-service-radio.py`: состояние, удержанный ввод при посадке,
  запуск/отмена, чужая миссия, срок запроса, переиспользование vehicle slot,
  потеря контекста, обе руки, материал/формат меша и повреждённые данные.
- `tools/test-driving-mission-inputs.py`: реальные pad callbacks, в том числе
  приоритет рации над газом и тормозом с сохранением другой педали.
- `tools/test-vehicle-doors.py`: production adapter редактора, оба контроллера,
  перенос/поворот рации, владение и сохранение на отпускании.
- `tools/test-service-radio-gpu.py`: реальный shader + формат вершин,
  разделение держателя/корпуса, движение PTT и изолированный цвет накладки.
- Hand actions, runtime selection, native sampler, Blender GLB roundtrip
  и GPU shader проверяют все 15 клипов.

Проверка ощущений, расположения и фактического запуска/отмены в Quest
остаётся за пользователем. Полный деплой нужен из-за изменения hand assets.
