# 31 — ABI совместимости гидравлики и дебаг-предпросмотр

Дата: 16.11.2026. Статическое исследование Android ARM64 2.11.311.
Игровой код не менялся; игра и установка на Quest не запускались.

## Результат для дебаг-меню

На текущем валидном автомобиле совместимость определять отдельно от установленного
оборудования: штатный тип автомобиля и отсутствие `HydraulicNone` в handling flags.
В целевом ELF `CAutomobile::HydraulicControl` немедленно выходит при этом флаге.
Отдельного экспортированного предиката `CanInstallHydraulics` при просмотре
экспортов/дизассемблирования не обнаружено. Для мода нужен небольшой read-only wrapper:

```cpp
// Вызывать на игровом потоке только после проверки живого CVehicle*, modelId
// и таблицы моделей. Функции не принимают взаимозаменяемые this-указатели.
using IsCarModelFn = bool (*)(std::int32_t modelId);
using GetUpgradeFn = std::int32_t (*)(void* vehicle, std::int32_t slot);

std::uint32_t flags;
std::memcpy(&flags, static_cast<const std::uint8_t*>(vehicle) + 0x4B8, sizeof flags);
const bool supportsHydraulics = IsCarModel(modelId) && (flags & 0x40000u) == 0;
// Наличие — отдельный вопрос. GetUpgrade обходит clump; нужны валидные
// загруженные геометрия и экземпляр, одного model info недостаточно.
const bool installed = supportsHydraulics && GetUpgrade(vehicle, 16) != -1;
```

Это критерий совместимости механики на текущем автомобиле, а не разрешение
конкретного мод-гаража, миссионного скрипта или текущего игрового состояния.
Для моделей без живого экземпляра он не выдаёт ответ: нужна отдельная проверка
исходных handling data. Дебаг кокпита работает с текущей машиной.

| Совместимость | Оборудование | HYDRAULICS и предпросмотр в дебаге |
| --- | --- | --- |
| Да | Не установлено | Показать, разрешить калибровку |
| Да | Установлено | Показать, разрешить калибровку |
| Нет | Любое, включая принудительную выдачу | Скрыть |
| Невалидная/незагруженная машина | Неизвестно | Временно скрыть; не кэшировать как несовместимость модели |

Предпросмотр не устанавливает апгрейд, не выделяет специальную коллизию,
не подаёт управляющие оси и не меняет положение подвески. Положение/размер/поворот
узла сохраняются по модели. В обычной игре нужны отдельные проверки оборудования,
водителя и режима. Флаг `HydraulicGeom` учитывать отдельно для штатной геометрии:
текущий мод допускает `(HydraulicGeom | HydraulicInst) && !HydraulicNone`;
`GetUpgrade(16) == -1` сам по себе не доказывает несовместимость машины.

## Связь с исследованием задачи 32

[Исследование нитро](NITRO_ABI_RESEARCH_32.md) правильно разделяет совместимость
модели и оборудование экземпляра. Это разделение применимо и здесь, но
`CVehicleModelInfo::IsUpgradeAvailable(slot)` нельзя переносить как готовый
предикат гидравлики заменой `15` на `16`.

Функция по RVA `0x5354C4` только проверяет `parent component ID >= 0` по адресу
`*(modelInfo + 0x90) + 0xD0 + slot * 0x20`. Она не читает `HydraulicNone`.
Нитро имеет проверку места крепления в пути установки, а гидравлика обрабатывается
отдельной веткой `SetVehicleUpgradeFlags`, выставляющей флаг оборудования без
проверки места крепления. Поэтому наличие/отсутствие dummy-узла не заменяет
проверку механической совместимости гидравлики.

Важное отличие от старого PC-заголовка: Android-конструктор `CVehicleStructure`
по `0x53310C` инициализирует **18** parent ID, от `+0xD0` до `+0x2F0` с шагом
`0x20`. Слот 16 не выходит за этот Android-массив. Причина не использовать
`IsUpgradeAvailable(16)` — смысл предиката, а не доказанный выход за границы.

## Подтверждённые экспорты и смещения

| Назначение | Экспорт | RVA, размер |
| --- | --- | --- |
| Проверка типа модели автомобиля | `_ZN10CModelInfo10IsCarModelEi` | `0x531E78`, `0x5C` |
| Наличие апгрейда экземпляра | `_ZN8CVehicle10GetUpgradeEi` | `0x6E4A24`, `0xD8`; гидравлика — слот 16 |
| Штатное управление гидравликой | `_ZN11CAutomobile16HydraulicControlEv` | `0x6A1F8C`, `0xB94` |
| Установка флагов апгрейда, НЕ предикат | `_ZN8CVehicle22SetVehicleUpgradeFlagsEiiRi` | `0x6E46E4`, `0x13C` |
| Выделение/получение специальной коллизии, НЕ чистый getter | `_ZN8CVehicle18GetSpecialColModelEv` | `0x6E3CBC`, `0x124` |

RVA — для сверки, не абсолютные адреса процесса. Подключать через разрешение
экспортов, как другие ABI проекта. `IsCarModel` принимает model ID в `w0`,
возвращает 0/1 в `w0`. Перед вызовом проверить индекс и существующую таблицу
моделей: функция сама проверяет ненулевой model info, но не диапазон индекса.
Она проверяет виртуальный `GetModelType() == 6`, затем vehicle type `+0x6C == 0`.
Байки/лодки/самолёты и другие типы не считать совместимыми по одному отсутствующему
флагу запрета. Поддержку специальных подклассов автомобиля не расширять без
отдельной проверки их игрового пути.

Флаги экземпляра: `uint32_t` по `CVehicle + 0x4B8`:

- `HydraulicGeom = 0x10000` (бит 16).
- `HydraulicInst = 0x20000` (бит 17).
- `HydraulicNone = 0x40000` (бит 18); тот же бит — bit 2 байта `vehicle + 0x4BA`.

## Проверенные инструкции

Запрет в `CAutomobile::HydraulicControl` проверяется в двух входных путях:

```asm
6a2008: 3952ea68  ldrb w8, [x19, #0x4ba]
6a200c: 37105688  tbnz w8, #2, 0x6a2adc  ; общий выход
...
6a2018: 3952ea68  ldrb w8, [x19, #0x4ba]
6a201c: 37105608  tbnz w8, #2, 0x6a2adc
```

`GetUpgrade(16)` после обхода atomics проверяет установленное оборудование:

```asm
6e4a88: 7100429f  cmp  w20, #0x10
6e4a8c: 540001a1  b.ne 0x6e4ac0           ; вернуть -1
6e4a90: 3952ea68  ldrb w8, [x19, #0x4ba]
6e4a94: 36080168  tbz  w8, #1, 0x6e4ac0  ; HydraulicInst отсутствует
6e4a98: 90000aa8  adrp x8, 0x838000
6e4a9c: f943c908  ldr  x8, [x8, #0x790]   ; GOT: MI_HYDRAULICS
6e4aa0: 1400000c  b    0x6e4ad0           ; ldrh w0, [x8]
```

Связь `0x838790` с `MI_HYDRAULICS` подтверждена ELF-релокацией, а не только
совпадением номера слота. В `SetVehicleUpgradeFlags` ветка `slot == 16`
по `0x6E4700…0x6E4728` выставляет `0x20000`, пишет поля экземпляра и возвращает
успех. Она не проверяет `HydraulicNone`; пробная установка не является проверкой.

`ProcessControl` по `0x6A85CC…0x6A85E0` в отдельной штатной ветке также может
выставить `HydraulicInst` перед вызовом `HydraulicControl`. Флаг наличия нельзя
использовать вместо независимой совместимости в меню.

`GetSpecialColModel` по `0x6E3D48…0x6E3DA8` записывает индекс/владельца специальной
коллизии, регистрирует ссылку и при необходимости выделяет данные. Его, как и
`AddVehicleUpgrade`, `SetVehicleUpgradeFlags` и `HydraulicControl`, не вызывать
для read-only предпросмотра.

## Контракт реализации — 16.11.2026

На том же Android ELF дополнительно подтверждены экспорты и первые четыре
инструкции, проверяемые перед установкой trampoline:

| Функция | RVA | Слова ARM64 |
| --- | --- | --- |
| `_ZN11CAutomobile16HydraulicControlEv` | `0x6A1F8C` | `d10403ff 6d063bef 6d0733ed 6d082beb` |
| `_ZN4CPad12HornJustDownEv` | `0x49D76C` | `a9be7bfd f9000bf3 910003fd 79422008` |
| `_ZN16CAEAudioHardware11GetBeatInfoEP9tBeatInfo` | `0x378D5C` | `a9bd7bfd f9000bf5 a9024ff4 910003fd` |

`HydraulicControl` использует `HornJustDown` для перехода между значениями
`60` и `500` в `uint16 vehicle+0xA88`. HIGH определяется как значение ≥500.
Состояние нужно читать из игры, а не сохранять в отдельном переключателе VR.
Перехват `HornJustDown` заменяет событие только в thread-local области вызова
`HydraulicControl` текущей машины с физическим VR-управлением. За её пределами
остаётся оригинальный клаксон. MODE передаёт не более одного события на вызов;
после второго VR-отзыва событие снимается только при фактической смене LOW/HIGH
после возврата из оригинального `HydraulicControl`, а не в момент чтения
`HornJustDown`. Пропущенный запрос или отсутствие смены состояния не теряют
ожидающее нажатие. Отпускание Grip не сбрасывает нативное положение.
Программной инверсии команд X/Y нет.

Для обычного управления нужны совместимость и хотя бы один из флагов
`HydraulicGeom|HydraulicInst`; для дебаг-предпросмотра достаточно совместимости.
Предпросмотр изолирован от нативного управления, его MODE меняет только индикацию.

Чтобы упростить LOWGAME согласованно со штатным подсчётом очков, после оригинального
`GetBeatInfo` нормализуются **и внутреннее окно** `hardware+0xCE8`, и возвращённая
копия `tBeatInfo`. Окно содержит 20 пар `uint32 time,key`; далее поля present
(`+0xA0`), last key (`+0xA4`) и index (`+0xA8`). Меняются только ключи: `5→1`,
`6→2`, `7→3`, `8→4`, `11→9`, `12→10`, `15→13`, `16→14`. Время, индекс и остальные
направления сохраняются. Нормализация включена только при активной LOWGAME;
пляжные танцы и другие музыкальные события не меняются. Вместе с ограничением
джойстика это сохраняет одинаковые задания у подсказок и нативного судьи.

`tools/test-vehicle-hydraulics.py` сверяет инструкции с локальным целевым APK,
вызывает production-адаптеры на фикстурах и проверяет изоляцию обычного клаксона,
дебаг-режима и миссии. Это не заменяет прохождение миссии в шлеме.
