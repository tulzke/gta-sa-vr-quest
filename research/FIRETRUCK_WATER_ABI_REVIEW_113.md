# 113 — Водомёт Firetruck: Android ABI и выбор прицела MVP

Дата: 17.11.2026. Статическое исследование пользовательской Android ARM64 2.11.311.
Игровая реализация не изменена; поведение в Quest не проверялось.

## Решение для MVP

После обсуждения сложности дуги пользователь выбрал прицел как в Helldivers:
неподвижный центральный целеуказатель камеры и отдельный кружок фактического
направления сопла. Камера сразу следует двум осям пульта, сопло с ограниченной
скоростью догоняет цель. Кружок показывает направление сопла, а не гарантированную
точку попадания воды с учётом гравитации. Предсказание дуги отложено.

Ниже сохранено исследование для будущего этапа и интеграции самого водомёта.

## Экспортированные точки входа

RVA относятся только к указанному ELF; не переносить PC-адреса и размеры структур.

| Экспорт | RVA | Размер | Назначение |
| --- | --- | --- | --- |
| `_ZN11CAutomobile16FireTruckControlEP5CFire` | `0x5FA414` | `0x618` | Наведение и создание воды; `this`, `CFire*` |
| `_ZN13CWaterCannons9UpdateOneEjP7CVectorS1_` | `0x5FA1D8` | `0x160` | `uint32 id`, указатель на позицию, указатель на начальную скорость |
| `_ZN12CWaterCannon15Update_NewInputEP7CVectorS1_` | `0x5F9954` | `0x54` | Записать позицию и скорость в текущую секцию |
| `_ZN12CWaterCannon19Update_OncePerFrameEs` | `0x5F92D4` | `0x270` | Обновить секции; `this`, `int16 index` |
| `_ZN13CWaterCannons6UpdateEv` | `0x5FA338` | `0x80` | Обновление трёх водомётов |
| `_ZN12CWaterCannon6RenderEv` | `0x5F99A8` | `0x73C` | Визуализация, проверка препятствий и брызги |
| `_ZN13CWaterCannons8aCannonsE` | `0xCC65E8` | `0xBE8` | Три объекта, шаг `0x3F8` |

В `UpdateOne` аргумент с именем `end` в публичных заголовках означает скорость,
а не конечную точку дуги. Готового экспортированного запроса, который по углу
возвращает будущую траекторию, среди функций этих классов не обнаружено.

Подтверждённые поля объекта: ID `+0x00`, текущий индекс секции читается как
signed short по `+0x04`, время создания `+0x08`, 32 позиции `CVector` по `+0x0C`,
32 скорости по `+0x18C`, 32 флага по `+0x30C`, начало аудио по `+0x330`.
Полный layout аудио здесь не исследован. PC `sizeof(CWaterCannon) == 0x3CC`
не подходит для Android ARM64 (`0x3F8`).

## Что определяет дугу

### Повторная проверка по замечанию о дальности — 17.11.2026

Нативный код пульта задаёт углы и создаёт секцию с той же начальной скоростью
`0.5*dWorld`, тем же разбросом и поправкой движения машины. Ускорение падения,
обновление секций и тушение остаются в оригинальном `CWaterCannon`. Никакого
нового коэффициента ослабления или искусственно короткой дальности не добавлено.

Однако «штатная скорость» не означает подтверждённую штатную дальность в VR:

- Пульт направляет сопло по абсолютному направлению руки. Штатный режим камеры
  `0x12` добавляет к её вертикальному углу около **+15°**; в пульте этой
  скрытой добавки нет. Кружок показывает ось сопла, а не баллистическое
  попадание. Для удалённой цели струю приходится поднимать над ней.
- В `Update_OncePerFrame` после стартовых 150 мс индекс увеличивается на один
  и берётся modulo 32 (`0x5f9300..0x5f932c`). При этом движение учитывает
  `CTimer::ms_fTimeStep`, а время жизни задаётся количеством обновлений.
  Поэтому при увеличении игрового FPS секция успевает пролететь меньше до
  перезаписи. Для неподвижной машины с нормальным ходом времени горизонтальная
  скорость — около 25 м/с; предел по 32 кадрам даёт примерно **27 м при 30 FPS,
  22 м при 36 FPS, 11 м при 72 FPS** от точки создания, без учёта падения,
  столкновений и точного порядка обновлений. Это расчётное объяснение,
  **не измерение текущего FPS или дальности в Quest**. Частота дисплея сама
  по себе не доказывает такую же частоту игровой симуляции.
- Штатный Render делает старые секции прозрачнее: alpha приблизительно
  `64*(1-age/32)` (`0x5f9c68..0x5f9c7c`). Видимое ослабление хвоста поэтому
  ожидаемо. Вызов тушения получает постоянные аргументы `2.0f, 0.5f` для
  активной секции (`0x5f93e4..0x5f93f8`); пульт их не меняет.

Отпечатки перечисленных инструкций добавлены в `tools/test-water-monitor-retail.py`.
В этой итерации физика, скорость и время жизни воды **не изменялись**. Чтобы
решать вопрос нормализации дальности, остаётся измерить именно игровую частоту
и реальный результат тушения на устройстве; сравнивать при одинаковых углах.

Начальная скорость зависит от двух углов сопла, матрицы машины и её скорости.
Для Firetruck направление в локальных осях машины:

```text
dLocal = (-sin(yaw) * cos(pitch), cos(yaw) * cos(pitch), sin(pitch))
dWorld = carRotation * dLocal
v0 = 0.5 * (dWorld + (0, 0, r / 1000)) + (carVx, carVy, 0.3 * carVz)
r = rand() & 15
```

Штатный источник — мировая позиция узла по `vehicle+0x8A0`, смещение вперёд
на `1.2*dWorld` и поправка движения точки машины через `CPhysical::GetSpeed*dt`.
Без узла используется преобразованная машиной точка `(0, 1.5, 1.8)`.

В `Update_OncePerFrame` для активной секции сначала обновляется скорость, затем
позиция (полунеявный Euler):

```text
v.z += -0.004f * dt
p += v * dt
```

`dt` — внутренний `CTimer::ms_fTimeStep`, не секунды. Его GOT-ссылка `0x837478`.
Константа ускорения собрана инструкциями `0x5F9334/0x5F9344` из битов
`0xBB83126F`; обновление Z — FMADD по `0x5F9380`, перенос позиции —
`0x5F9390..0x5F93A8`. Используется кольцо из 32 секций: после начальных
150 мс текущий слот сдвигается при каждом обновлении. Горизонт предсказания
нужно связывать с этим временем жизни и игровым timestep.

Вывод: изменение вертикального угла действительно меняет форму/дальность дуги.
Дугу можно предсказывать теми же шагами без создания реальной воды. Случайная
вертикальная добавка к `v0` у Firetruck — `0..0.0075` во внутренних единицах;
будущий прогноз является средней траекторией, а не точным рисунком всех секций.
Во время подачи реальные секции можно читать для сверки. При быстром наведении
старые секции продолжают движение по ранее полученным скоростям.

## Наведение и интеграция

Углы читаются по `vehicle+0xB80` (yaw) и `+0xB84` (pitch). Для Firetruck
ограничение pitch — примерно `-20°..+20°`; yaw нормализуется вокруг `±pi`.
В штатной ветке камеры mode `0x12` уже есть ограниченная скорость следования:
`0.05*dt` для yaw и `0.02*dt` для pitch, с поправкой pitch камеры на `15°`.
Это сведения о штатном пути, а не автоматически выбранные настройки пульта.

Мобильная функция вне mode `0x12` пропускает этот расчёт и сохраняет текущие
углы; вызовов `GetCarGunUpDown/LeftRight` в просмотренном теле нет. Поэтому
подключение осей к общим CarGun-хукам само по себе не обеспечит наведение.
Подача подтверждённо читает `GetCarGunFired(true, false)` по `0x5FA7C8`.
Изолировать управление пульта моделью 407 и игроком, сохранить NPC-путь.

У `CWaterCannon::Render` есть побочные эффекты: `rand`, `ProcessLineOfSight`,
создание частиц и обновление splash audio. Дополнительная камера не должна
повторно исполнять игровое обновление, тушение или эффекты за тот же кадр.
Для MVP-кружка достаточно безопасного снимка фактического направления сопла
и проекции точки вдоль него в камеру пульта; не вызывать `UpdateOne` или
`Update_OncePerFrame` для отрисовки прицела. Правило выбора глубины/точки на луче
и обработку ухода за край кадра проверить при реализации.
