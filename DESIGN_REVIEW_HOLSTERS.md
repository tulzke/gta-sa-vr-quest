## 1. Основные замечания

| Приоритет | Наблюдение и риск | Предлагаемое решение |
| --- | --- | --- |

## 2. Единая система координат

Сейчас `GetHolsterAnchorTracking` (`VrCamera.cpp:29949`) строит точку через
`g_origin`, а `HolsterWeaponMatrix` (`:2702`) строит модель через `g_vrBase`.
`EnsureOrigin` (`:2455`) уже сохраняет только yaw: наклоны головы не должны
появиться в новой привязке. `TrackingPointToGame` / `TrackingVectorToGame`
(`:2882, :2888`) дают существующий путь преобразования в игровой мир.

Предлагаемый источник истины — `HolsterBodyFrame` в OpenXR LOCAL:
позиция опоры, yaw, valid, epoch, frameId и вычисленные socket poses.
Опора остаётся на уровне головы, поскольку существующие `vertical` уже
отрицательны относительно неё; повторно вычитать высоту торса нельзя.

Для точки i:

```text
socketLocal[i] = bodyPosition + yawRotation * (lateral, vertical, -depth)
socketGame[i]  = TrackingPointToGame(socketLocal[i])
```

Маркер и проверка расстояния используют `socketLocal`. Модель получает ту же
точку и повёрнутые оси через преобразование в игровой мир, затем существующую
ориентацию оружия и калибровку. Сохранить отражённый базис RenderWare и знаки
для задних точек; преобразование к одному quaternion может потерять отражение.

**Уточнение требования совпадения:** калибровка `HolsterCalib` намеренно
смещает/вращает только модель (`Calib.h:49–53`, `VrCamera.cpp:2718`). Совпадать
должны исходная socket pose и её преобразования. Центр откалиброванной модели
не обязан совпадать с маркером. Перенос зоны захвата вслед за `offX/Y/Z` изменит
уже настроенную механику и не нужен для этой фичи.

Поворот корпуса не пишет в `g_origin`, `g_vrBase` или locomotion. Виртуальный
поворот стиком учитывается существующим преобразованием в мир ровно один раз;
в LOCAL дополнительный stick yaw не добавляется.

## 3. Алгоритм условного корпуса

Предлагается небольшой самостоятельный модуль расчётов без GTA/OpenGL, который
получает позы и время извне. Его производственный код можно тестировать на ПК.

Начальные параметры прототипа:

| Параметр | Значение |
| --- | --- |
| Немедленный запуск догоняющего поворота | отклонение ≥ 45° |
| Отложенный запуск | отклонение ≥ 20° в одну сторону непрерывно 0,7 с |
| Остановка | отклонение ≤ 10° |
| Постоянная сглаживания yaw | 0,3 с |
| Максимальная скорость | 90°/с |

Ошибка yaw берётся по кратчайшей дуге через ±180°. При смене стороны или
возвращении ниже 20° таймер сбрасывается. После запуска догонять до зоны 10°,
а не требовать сохранения стартового порога. Шаг вычислять через
`1-exp(-dt/tau)` с ограничением угловой скорости и без перелёта через цель.
Длительный разрыв кадров/невалидный трекинг обрабатывать как прерывание,
а не как большой интеграционный шаг. Порог разрыва для прототипа — 0,25 с.
При почти вертикальном взгляде сохранять последний надёжный yaw: проекция
forward на горизонтальную плоскость становится вырожденной.

Позиция в первом прототипе следует валидной позиции HMD по XYZ без длинного
фильтра: шаг по комнате и физическое приседание не должны оставлять пояс позади.
Это также переносит пояс при наклоне тела — известное ограничение оценки по HMD.
Поворот головы без изменения позиции не изменяет высоту точек. Игровое приседание
уже может менять базу камеры; не добавлять его высоту повторно в LOCAL.
Различать наклон и шаг достоверно без дополнительных данных нельзя; оценку
смещения от шеи стоит добавлять только после наблюдаемой проблемы на Quest.

### Защита от «убегающего» холстера

Проверять близость к предыдущему валидному снимку до интеграции yaw. Для пустой
руки рассматривать доступные точки захвата, для удерживающей — только точку
её слота. Руку поддержки и руку на руле исключить из намерения взять оружие.

Начальный радиус остановки — соответствующий радиус действия + 8 см;
выход — ещё на 5 см дальше. Возобновлять поворот после 0,2 с вне внешней зоны,
сбросив таймер отложенного запуска. Замораживать yaw всего корпуса, а не
отдельные точки; позиция продолжает следовать игроку. Обе руки могут удерживать
остановку, пока хотя бы одна удовлетворяет условию.

Не вводить принудительный тайм-аут, который снова уводит точку от руки.
Риск: рука, постоянно лежащая у пояса, может удерживать старую ориентацию.
Это отдельный обязательный сценарий проверки удобства; предложенная защита
останавливает угловое движение, но не обещает устранить смещение при наклоне HMD.

## 4. Состояния и внешний вид маркера

Источником остаётся `physicalweapon::Update`, вызываемый из `main.cpp:1921`.
`holster::Update` — старый путь; изменять только его недостаточно.
Не снимать `OccupiedSlotMask` у рендера оружия: он правильно подавляет дубли
как для удерживаемого, так и для брошенного оружия (`VrCamera.cpp:21398`).

| Состояние слота в обычной игре | Маркер в SHOW | Модель на теле |
| --- | --- | --- |
| Оружие есть, не удерживается и не брошено | Куб захвата | Да |
| Оружие в любой основной руке | Кольцо с шевроном внутрь | Нет |
| Брошено, ещё не возвращено таймером | Нет | Нет |
| Пусто / оружие удалено из инвентаря | Нет | Нет |

Дополнительные правила:

- `HIDE`: нет модели и маркера; захват/возврат сохраняются.
- `OFF`: нет модели и маркера; захват запрещён, возврат разрешён как сейчас.
- Глобальное отключение маркеров скрывает оба вида подсказок, но не модели.
- Передача между руками не меняет socket: принадлежность определяется слотом.
- Оружие без назначенной точки не получает фиктивный маркер возврата.
- При смене loadout в меню маркер после закрытия следует актуальному назначению.
- Бросок расходуемого предмета должен учитывать `ReleaseAfterUse`: оставшийся
  запас снова даёт куб захвата, а не кольцо для уже использованного предмета.
- В транспорте куб захвата должен обещать только допустимый тип оружия.
  Кольцо определяется возможностью вернуть реально удерживаемый слот.

Для API предлагается массив `Marker { position, kind }`, где `kind` различает
захват, возврат, поддержку и preview. Не более семи body markers плюс один
support marker; кольцо **заменяет** куб. Публиковать массив целиком под текущей
блокировкой, а не передавать типы отдельно от позиций.

Кольцо: начальный внешний диаметр 7 см, заметная толщина, шеврон направлен
к центру кольца. Это обозначение места, не изображение сферы возврата 24 см.
Плоскость обращена к центру головы, одна и та же для двух глаз; не строить
отдельный billboard для каждого глаза. Позиция остаётся точно на socket.
Использовать существующий depth pass. Читаемость через тело/оружие и размер
проверить в шлеме; постоянный показ сквозь стены в первую версию не добавлять.
Цвет может помогать, но различимость обеспечивается геометрией. Вибрация
и подсветка в радиусе остаются необязательным следующим шагом.

Preview холстерной калибровки сейчас намеренно показывает все валидные точки,
включая пустые и занятые. Сохранить этот особый режим и блокировку взаимодействий.
Support calibration по-прежнему может принудительно показать свою точку при
выключенных обычных подсказках. Запрет дублирования модели относится к gameplay;
preview — существующее намеренное исключение.

## 5. Жизненный цикл, потоки и настройки

Снимок корпуса обновлять один раз до расчёта взаимодействий; рендер использует
его до следующего игрового тика. Позы головы и рук должны иметь совместимый
tracking epoch. Текущий код берёт руки в `PhysicalWeapon::Update`, а голову и
recenter — в camera hook: место подготовки общего снимка необходимо проверить
по реальному порядку этих вызовов. Просто вставить обновление в два геттера нельзя.

Не вызывать публичные геттеры `physicalweapon`, берущие `gMutex`, из расчёта,
который уже выполняется под этим mutex. Намерение руки передавать входными
данными; корпус не должен вызывать оружейную подсистему обратно.

При recenter, новой tracking epoch и смене режима привязки инвалидировать
снимок, таймеры и proximity latch. На следующей совместимой валидной позе
инициализировать заново. При потере поз не создавать интерактивные точки из
старой системы координат; после восстановления не выполнять накопленный grip
как новое нажатие. Не добавлять сброс владения оружием ради корпуса.

Для первой версии предлагается включать новый режим пешком, а в транспорте,
плавании, парашюте, джетпаке и специальных scripted cameras сохранять прежнюю
привязку и текущие ограничения оружия. На границах режима переинициализировать
корпус. Это консервативное предложение, которое сужает действие новой привязки;
его нужно явно принять в реализации, а не получить случайно из общего флага.

В меню достаточно `HOLSTER FRAME: BODY / RECENTERED`. Старые конфиги без ключа
сохраняют `RECENTERED`; BODY включается для испытаний. После проверки удобства
можно отдельно изменить default для новых установок. Сохранять выбор в
`vr_holsters.ini`, неизвестное значение заменять безопасным default. Пороги
пока оставить параметрами реализации, не перегружать ими пользовательское меню.

## 6. Порядок реализации и критерии приёмки

1. Зафиксировать таблицу состояний и добавить типизированные маркеры на старой
   привязке. Проверить возврат, бросок, передачу, видимость и поддержку.
2. Выделить общий снимок точек, сохраняя прежнюю геометрию. Проверить калибровку
   и преобразование LOCAL → game → LOCAL с ненулевыми origin и stick yaw.
3. Добавить алгоритм BODY, режим совместимости, lifecycle и защиту возле руки.
4. Выполнить сборку и проверку на Quest, подобрать параметры.

Автотесты должны запускать производственный код расчёта и переходов, а не
копию алгоритма. Существующий `tools/test-vr-recovery.py` показывает подход
с подменой внешних API и времени; новый компактный модуль лучше подключать напрямую.

Обязательные случаи: краткий взгляд 15°; устойчивый 30°; разворот 90°/180°;
переход через ±180°; почти вертикальный взгляд; сравнение 36/72/90 Гц и редких
кадров; обе руки у разных точек; уход/возврат в радиус; шаг и приседание;
recenter/epoch во время удержания; восемь маркеров; SHOW/HIDE/OFF × глобальный
переключатель; передача/поддержка/бросок/расходование предмета; смена loadout;
калибровка; вход/выход из транспорта и специальных режимов.

Для геометрии проверять совпадение socket после преобразований с погрешностью
не более 1 мм, отдельно от намеренного model calibration offset. Проверять,
что модель, маркер и взаимодействие используют один frameId. При одинаковой
траектории и времени yaw на разных частотах должен расходиться не более чем
на 1° вне границ дискретных переходов; при разрыве поз должно сработать восстановление.

На Quest главный критерий: после оглядывания и физического разворота игрок
находит все семь точек привычным движением, а подход руки не уводит цель.
Отдельно проверить руку, оставленную у пояса, наклон с протянутой рукой,
Grip Lock, калибровочный preview и читаемость кольца в обоих глазах.
