# Пользовательские анимации рук

Локальный исходник — `BothHands.blend` (Blender 4.5). Рабочий меш —
`HandRight`, скелет — `Hand`. Резервный скелет `Backup`, его меши и перчатки
не экспортируются. В исходном файле ничего не изменяется и не сохраняется.

Экспорт всех девяти Actions:

```powershell
& 'C:/Program Files/Blender Foundation/Blender 4.5/blender.exe' --factory-startup -b assets/vrhands/BothHands.blend --python-exit-code 1 --python tools/export_hand_actions.py -- --output assets/vrhands/animations
```

| Имя в экспорте | Имя Action в текущем исходнике | Диапазон кадров |
|---|---|---|
| Grip | Grip | 1–21 |
| Pinch | Pinch | 0–21 |
| Point | Point | 0–21 |
| OpenPalm | OpenPalm | 0–21 |
| Beckon | Beckon | 0–26 |
| GripPistol | GripPistol | 0–21 |
| GripPistolOffhand | GripPistolOffhand | 0–21 |
| Fist | Fist | 0–21 |
| GripPistolShoot | GripPistolShoot | 0–5 |

Пробелы и регистр в именах Actions не учитываются. Суффикс `_R` не нужен.
Диапазон определяется по ключам самой Action, а не по диапазону воспроизведения
сцены. Экспортируются все целые кадры и все дробные кадры с ключами. Движение
вычисляется Blender с учётом модификатора Armature и кривых анимации.
Исходный масштаб — сантиметры; координаты экспортируются в метрах.
Размещение меша и скелета в сцене не переносится в игровые координаты.

## Файлы и воспроизведение

`animations/manifest.json` содержит исходный FPS, диапазоны, длительности,
кадры и соответствие каждого кадра номеру блока и слоту позы. Каждые четыре
последовательных отсчёта записываются в отдельный UXRH v1. Последний блок
дополняется копиями последнего отсчёта; его действительное число отсчётов
указано в `count`. Позиции, нормали, UV и индексы сохраняют структуру UXRH.

**Четыре слота этих файлов — последовательные кадры анимации.** Они не имеют
значений open/grip/trigger/both обычной модели руки. Нельзя заменять ими
`BigHandRight.uxrh` и рассчитывать на прежнее смешивание grip/trigger.

У каждого блока есть правая и зеркальная левая версия. Левая отражается
по локальной Y, с отражением нормалей и обратным порядком индексов треугольников.
Обе версии сохраняют UV и порядок вершин правого эталона. Они не обязаны
совпадать с порядком вершин прежней отдельной модели `BigHandLeft.uxrh`.
При подключении к рендереру нужно использовать согласованные меш/UV/индексы
для обеих рук и проверить базисы и смещения взаимодействий на Quest.

Нативный потребитель `native/src/HandAnimation.h` находит соседние отсчёты
по исходным номерам кадров, смешивает позиции и нормали; рендерер нормализует
результат нормалей после преобразования в пространство отображения.
Прогресс 0–1 соответствует диапазону `start`–`end`; уменьшение прогресса
воспроизводит разжимание. Точное воспроизведение между отсчётами — приближение
авторской скелетной анимации. При необходимости экспорт можно уплотнить.

## Подключение в игре

Полная сборка включает правые блоки и `timing.txt` всех девяти Actions, если
локальный экспорт присутствует. Отдельные левые блоки в APK не нужны: текущий
рендерер уже отражает каноническую геометрию базисом каждой руки. Повторное
отражение локальной Y здесь отменило бы нужное отражение. Это уточнение к
офлайн-экспорту левых мешей выше. Обе руки имеют независимый прогресс.

`EnsureHandAssets` целиком загружает согласованную библиотеку, проверяет её UV
и индексы относительно правого эталона. При отсутствии или повреждении файлов
сохраняется прежний рендеринг рук. Состояния оружия захватываются в том же
стереокадре, что положение рук и игровые изображения.

| Состояние | Новая анимация |
|---|---|
| Свободная рука, кнопки отпущены | Общая начальная открытая поза |
| Только grip | Grip, по силе нажатия |
| Только trigger | Point, по силе нажатия |
| Grip и trigger вместе | Fist |
| Ключ зажигания или крутилка радио | Pinch |
| Перетаскивание дебаг-маркера зажигания или радио | Pinch, только у перетаскивающей руки |
| Руль и рукоятки мотоцикла | Grip |
| Подтягивание/перелезание | Grip |
| Баскетбольный мяч | OpenPalm |
| Стрелковое оружие (типы 22–34 и 38), trigger отпущен | Конец GripPistol = начало GripPistolShoot |
| Стрелковое оружие, trigger нажат | GripPistolShoot, по силе нажатия |
| Холодное, прочее оружие и текущая поддерживающая рука | Grip |
| GripPistolOffhand, Beckon | Загружены, автоматическое включение не назначено |

Частичные нажатия образуют непрерывную поверхность Grip/Point/Fist: вдоль осей
используются авторские переходы, при одинаковом нажатии обеих кнопок — переход
Fist. Порог разрешения удара остаётся прежним: grip >= 0.65, trigger >= 0.45;
анимация не заменяет проверку скорости удара. Для оружия и контекстных хватов
приоритет выше обычных жестов, поэтому trigger не превращает их в Point.
Начало GripPistolShoot совпадает с концом GripPistol. Offhand пока не используется
по просьбе пользователя; его нельзя автоматически назначать поддержке пистолета.

Смещения и калибровки хватов сохранены от прежних моделей. После замены нужно
проверить в Quest обе руки, хват оружия и положение указательного пальца,
контакт с рулём, ключом, радио, мячом и опорами при перелезании. Авторские
новые формы могут потребовать корректировки этих калибровок.

Исходный `.blend`, его резервные копии и папка `animations/` остаются локальными
и исключены из Git. LFS для них не настраивается. Скрипты и эта документация
могут коммититься отдельно от ассетов.

Проверка локального экспорта без Blender:

```powershell
python tools/test-hand-actions.py
python tools/test-hand-animation-runtime.py
```

Проверяются диапазоны и покрытие кадров, топология и UV относительно правого
эталона, целостность блоков, нормали, масштаб, зеркальность, общий старт всех
обычных Actions и различие конечных жестов. Отдельно проверяются нативная
загрузка, интерполяция на границах блоков, выбор жестов и безопасный отказ
на повреждённых файлах. Ощущения и размещение рук требуют проверки в Quest.
