## Работающий фотоаппарат с экраном и сохранением снимков через API [В РАБОТЕ]

Сделать игровой фотоаппарат работающим в VR. Добавить экран по аналогии с экраном на базуке, хват основной руки как у пистолета и опору второй руки под объективом. Съёмка должна соответствовать направлению фотоаппарата и изображению на его экране.

Сохранять фотографии через доступный API. При реализации исследовать наличие универсального API; если его нет, проверять доступность API конкретной системы, шлема или среды и выбирать поддерживаемый способ. Не предполагать наличие платформенного API без проверки. При недоступном сохранении или ошибке сообщать об этом, не показывая ложный успех.

Проверить в Quest экран, кадрирование, съёмку и фактическое сохранение снимка, повторные снимки, хват каждой рукой и поддержку под объективом. Проверить доступность API, необходимые разрешения, отказ в доступе и неподдерживаемую среду. Сохранить штатные игровые события фотографирования, где они нужны миссиям.

Отдельной задачи на фотоаппарат не найдено. Для хвата учесть реализацию [задачи 20](ARCHIVE/20-dvuruchnyy-khvat-odnoruchnogo-oruzhiya.md); выбор API и совместимость исследовать при реализации.

### Дизайн-ревью · 17.11.2026

**Предлагаемое взаимодействие.** Пока фотоаппарат в любой руке, на задней панели работает прямоугольный видоискатель. Игрок может фотографировать на уровне груди, смотреть в сторону и поднимать фотоаппарат одной рукой. Указательный триггер ведущей руки делает один кадр за нажатие. Ведущая кисть использует пистолетный хват, на объективе калибруются отдельная точка и поза опоры второй руки. Хват поддержки добровольный. Для первого прототипа ведущая рука задаёт ось объектива, ведомая следует за точкой опоры. Это позволяет отдельно проверить, нужен ли двухручный поворот и как он ощущается при малом расстоянии между руками.

**Кадр с объектива.** Тип 43 сейчас включает при поднесении к глазу полноэкранный зум. `BuildPhotoView` и `FirePhotograph` строят кадр по позе головы. Предлагается брать положение и ориентацию объектива из того же откалиброванного трансформа, которым рисуется корпус, и отдельно калибровать положение заднего экрана. Переиспользовать рендер в текстуру из `WeaponOpticRender.inl` с прямоугольной экранной поверхностью. Для прототипа — 4:3, 768×576. Экран, фотоснимок и штатная проверка цели должны получать одну позу и проекцию на спуске. Зафиксировать кадр видоискателя при спуске, кратко показать его на экране, взять пиксели из той же текстуры и рисовать индикацию отдельно поверх. Проверить совпадение границ, ориентации и зума файла с видоискателем. Поворот головы при неподвижном фотоаппарате не меняет кадр. Глубина и детализация существующего дополнительного прохода требуют ранней проверки в Quest, особенно для далёких персонажей при сильном зуме и прозрачных объектов.

**Совместимость с игрой.** Сохранить `CWeapon::Fire` и временную подстановку режима 46, матриц и FOV, восстановив состояние игры сразу после вызова. Передавать им параметры захваченного кадра. Сохранить зум на вертикали правого стика и убедиться, что при максимальном зуме `GET_CAMERA_FOV` (`0x0801`) по-прежнему проходит штатный порог 20°. У текущего теста зафиксирована привязка к голове, её следует заменить проверкой привязки к объективу и независимости от HMD, сохранив проверки восстановления состояния и соседних опкодов. Успех игрового фотографирования и успех записи файла — два отдельных события. Ошибка записи не отменяет фото для миссии и не блокирует следующие нажатия.

**Сохранение.** В просмотренной спецификации OpenXR и документации Meta универсальный API записи кадра игрового объектива не найден. Системный захват и Media Projection берут ракурс пользователя. Для Quest предлагается сохранять пиксели игрового видоискателя в JPEG через Android `MediaStore.Images` в `Pictures/SAVR`. На Android API 29+ для публикации собственных снимков дополнительных разрешений на хранилище не требуется. Поддержку записи и видимость файла в интерфейсе Quest нужно подтвердить на устройстве. Считывание пикселей выполнить в очереди рендера с ограничением числа ожидающих операций, кодирование и запись вынести в рабочий поток. Публиковать через `IS_PENDING` и удалять незавершённую запись при ошибке. Сообщать «Сохранено» после публикации. При отказе, ошибке или недоступном API показывать «Не удалось сохранить» с сохранением штатного результата съёмки. [OpenXR](https://registry.khronos.org/OpenXR/specs/1.1/html/xrspec.html#rendering) · [Horizon OS](https://developers.meta.com/vr/documentation/android-apps/features-overview/) · [Android MediaStore](https://developer.android.com/training/data-storage/shared/media)

**Первый прототип в Quest.** Сначала проверить задний экран, ось объектива, читаемость и дальние цели. Затем проверить в сюжетной сцене попадание в кадр, промах и порог зума, а для свободной съёмки — обе ведущие руки, опору, серию отдельных кадров, открытие записанного файла, отказ в записи и стабильность стереокадра при спуске. Видимость снимков в системной галерее и производительность пока не подтверждены.
