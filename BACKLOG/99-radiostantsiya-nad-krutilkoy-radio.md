### Предлагаемое поведение

- Постоянная однострочная надпись над основанием крутилки, видимая вместе с ней. Для чтения не нужны наведение, захват или недавнее переключение.
- Только название станции (`K-ROSE`, `RADIO LOS SANTOS`), без префикса `RADIO:`. При подтверждённом выключении — `RADIO OFF`, в соответствии с текущим английским интерфейсом.
- Светлый пиксельный текст с компактной полупрозрачной тёмной подложкой. Одинаковый стиль для всех станций; смена без мигания, увеличения размера и прокрутки.
- Начальные размеры для прототипа: высота букв около 10–12 мм, ширина области до 24 см, центр надписи около 8 см над центром основания. Текущие названия, включая самое длинное в имеющейся таблице `MASTER SOUNDS 98.3`, должны помещаться при сетке 5×7 с межсимвольным интервалом в один пиксель. Проверить расчёт ширины и читаемость в Quest; не уменьшать автоматически текст до нечитаемого размера.
- Надпись следует перемещению и повороту всего основания в Vehicle Debug. Рабочий поворот ручки на ±30° на текст не влияет. Отдельный захват или профиль калибровки текста в первой итерации не нужен.
- Предлагается закрепить плоскость текста относительно основания, как небольшую табличку. Читаемость сбоку и на мотоциклах проверить отдельно; если потребуется поворот к голове, использовать единую ориентацию для обоих глаз, сохраняя привязку к основанию.
- Надпись не участвует в выборе интерактивной цели и не меняет радиус захвата. Руки и салон перекрывают её по глубине; сквозь приборную панель текст не показывать.

### Внешний вид — предложение

- Плоская компактная табличка с мягко скруглёнными углами, без объёмного корпуса. Подложка — тёмный графит `#17191C`, начальная непрозрачность около 75%, радиус углов около 3 мм.
- Шрифт согласован: пиксельный, в стиле счётчика патронов. Сетка 5×7, квадратные пиксели без сглаживания, прямое начертание, названия прописными буквами по центру. Между символами один пиксель; масштаб одинаков по горизонтали и вертикали.
- Цифры переиспользуют существующие начертания `ammoDigit` из шейдера `Xr.cpp`. Добавить в том же стиле латинские буквы A–Z, пробел, дефис и точку для названий станций. Это собственный набор пиксельных глифов, а не шрифтовой файл из подсказок.
- Основной текст — мягкий белый `#F2F2EC`, без декоративной обводки и размытой тени. При `RADIO OFF` тот же размер и компоновка, цвет светло-серый `#C2C4C6`; смысл состояния передаётся самим текстом, а не только цветом.
- Высота таблички ориентировочно 25–30 мм при высоте букв 10–12 мм. Поля по горизонтали около 8 мм с каждой стороны, по вертикали около 5 мм. Ширина по длине названия, максимум 24 см; размер букв при смене станции сохраняется.
- Только одна строка: например, `K-ROSE`. Логотип, значок ноты, дополнительный заголовок, рамка и светящийся ореол не нужны. При смене станции текст заменяется сразу, без анимации.
- Название неподвижно и центрировано. При высоте глифа 12 мм максимальное текущее название из 18 символов занимает `(18×6−1)×12/7 ≈ 183 мм`, вместе с полями по 8 мм — около 20 см, что укладывается в предел 24 см. Проверить расчёт для всех названий; бегущую строку, многоточие и перенос строк в первой реализации не добавлять.

### Состояния и обновление

| Состояние | Отображение |
| --- | --- |
| Подтверждённая активная станция | Её актуальное название |
| Подтверждённое выключенное радио | `RADIO OFF`; крутилка остаётся доступной |
| Транспорт без радио | Скрыты надпись, крутилка и её взаимодействие — общее правило задачи 85 |
| Состояние ещё не получено / неподдерживаемый ID | Скрыта надпись; прежнее название и `RADIO OFF` не подставляются |
| Выход, смена транспорта, камера вне допустимого контекста | Старое состояние сбрасывается; отображение возвращается только с актуальными данными |

Читать фактическое состояние игры, а не вычислять станцию по щелчкам крутилки. Это покрывает X, grip+X и изменения со стороны игры. Вход в машину сразу показывает текущее состояние после его получения. При смене транспорта состояние должно принадлежать именно текущему экземпляру машины, включая пересадку в другую машину той же модели.

`Unknown` означает отсутствие достоверных данных у мода, а не гарантированную тишину: например, функция чтения станции может быть недоступна, пока сама игра воспроизводит радио. Если проверка Android-версии подтвердит, что конкретный ID означает выключение, он относится к `Off`, а не к `Unknown`. Надпись `UNKNOWN` игроку не показывать.

Это пока защитный сценарий дизайн-ревью, а не наблюдавшаяся неисправность. Уже сейчас станция читается повторно при каждом `UpdateInput`, поэтому разовый невалидный результат не должен навсегда отключать надпись. Сохранить повторное чтение в последующих обновлениях: после получения валидного состояния надпись автоматически восстанавливается. Не делать цикл немедленных повторов в одном кадре. Если AudioEngine ещё не готов, повторные обновления позволяют дождаться его появления; постоянно отсутствующий символ функции или неверное сопоставление ID повторным чтением не исправляются и требуют устранения причины.

### Замечания к исходному коду (до MVP)

1. **Семантика состояния требует проверки перед реализацией.** `Symbols.h` объявляет `CAudioEngine_GetCurrentRadioStationID` с результатом `signed char`. В `Driving.cpp` текущий трёхсекундный вывод допускает только `station >= 0`, а значения вне 1–12 подписывает как `RADIO OFF`. Это не подтверждает ни код выключения, ни отсутствие радио, ни корректность всех ID. Проверить функцию и перечисление для используемой Android-версии по локальным исходникам/дизассемблированию; при необходимости подтвердить наблюдением в игре. Не определять наличие радио по текущей станции.
2. **Зависимости 85 и 82 пока открыты.** `UpdateRadioKnob` исключает велосипеды и проверяет водителя, но общего определения транспорта без радио там нет. `CabinVisualContext` содержит частные ограничения камеры, а задача 82 требует общего правила принадлежности камеры CJ. Надпись должна использовать общие правила вместе с крутилкой; одного `radioVisible` недостаточно, чтобы объявить эти требования выполненными. Минимальные общие проверки потребуются до приёмки 99 либо вместе с соответствующими задачами.
3. **Оси и синхронизация позы.** Доступны `radioCenter/right/up/normal` в `WheelVisualState`. Использовать тот же снимок позы для основания и надписи в обоих глазах. На мотоциклах исходное поле `up` руля направлено вперёд, а `normal` — вверх; механический перенос автомобильной формулы может сделать надпись горизонтальной. Отдельно проверить дефолтную и сохранённую `RadioPose`, наклон мотоцикла и обновление tracking после камеры.
4. **Существующий вывод связан с HUD.** `PublishRadioText` добавляет строку к `TIMERS` на три секунды. Для постоянной надписи нужен самостоятельный путь отрисовки в пространстве, не зависящий от включения таймеров/HUD или наличия отслеживаемых кистей. По решению пользователя убрать дублирующий вывод мода в `TIMERS` после подключения новой надписи; штатное поведение игры отдельно не менять.

### Подтверждённый ABI Android 2.11

Прочитана локальная игровая библиотека `build/vehicle-lift-lever/retail.so` с экспортированными AArch64-функциями, используемая в предыдущих исследованиях ABI проекта:

- `CAERadioTrackManager::GetCurrentRadioStationID` (`0x38b738`) возвращает поле `+0xe9`, заменяя внутреннее `0xff` на `13`. `GetRadioStationName` (`0x38b2c8`) сопоставляет `12` с `FEA_MP3`, `13` с `FEA_NON`; ID `0` — не выключение обычной станции.
- Конструктор `CVehicle` (`0x6d8b24`) размещает `CAEVehicleAudioEntity` по `vehicle+0x198`. `Initialise` (`0x3968c8`) копирует настройки по `audio+0x94`, тип радио находится по `settings+0x1b`, то есть `vehicle+0x247`.
- `CheckForStationRetune` (`0x388a80`) проверяет тип настроек; обычное переключение станций допускается для типа `0`. Полицейский/служебный поток не считается переключаемым музыкальным радио.
- `StaticGetPlayerVehicleAudioSettingsForRadio` (`0x396734`) возвращает текущую привязку настроек. `TurnOnRadioForVehicle` (`0x398774`) публикует в неё адрес `audio+0x94`; это позволяет отличить текущую машину от предыдущей без предположений о её модели.
