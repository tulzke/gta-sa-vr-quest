# HTML-индекс бэклога

Страница: [index.html](index.html). Единственный источник данных страницы —
[index.json](index.json). Описания задач остаются в отдельных Markdown-файлах;
нажатие на название задачи открывает её файл в той же вкладке.
Старый [BACKLOG.md](BACKLOG.md) сохранён и ведётся параллельно.

## Открытие

Из корня репозитория, нужен только Node.js:

```powershell
node tools/backlog-server.mjs
```

Открыть <http://127.0.0.1:8765/>. Другой порт передаётся аргументом, например
`node tools/backlog-server.mjs 8766`. Сервер доступен только на этом компьютере,
работает только на чтение и отдаёт файлы из `BACKLOG`. Markdown открывается
как текст UTF-8. Остановка — `Ctrl+C`.

Можно открыть `index.html` двойным щелчком без сервера и выбрать соседний
`index.json` кнопкой на странице. Браузеры ограничивают автоматическое чтение
локальных файлов. После изменения JSON в этом режиме выбрать его повторно;
при работе через сервер достаточно обновить страницу.

## Данные

Категории, их названия и порядок задаются в массиве `categories`:

```json
{ "id": "vehicle-controls", "title": "Управление транспортом" }
```

`id` — уникальное имя из строчных латинских букв, цифр и дефисов,
начинающееся с буквы. Имя `all` зарезервировано.

Каждая запись `tasks` содержит:

```json
{
  "id": 9,
  "title": "Проверка положения руля на всех моделях автомобилей",
  "file": "09-proverka-polozheniya-rulya-na-modelyakh-avtomobiley.md",
  "categories": ["vehicle-controls", "vehicle-content"],
  "priority": "none",
  "status": "open"
}
```

- `id` — уникальный номер задачи; `file` — имя её Markdown-файла в этой папке.
- `title` — название без номера и метки `[В РАБОТЕ]`.
- `categories` — одна или несколько категорий по их `id`.
- `priority`: `critical` (критический), `high` (высокий), `medium` (средний),
  `low` (низкий), `none` (не задан). Изначально все задачи имеют `none`:
  приоритеты ещё не назначены. Категории распределены по темам задач.
- `status`: `open` (открыта) или `in_progress` (в работе).

По умолчанию задачи отсортированы от высокого приоритета к низкому.
`none` всегда идёт после назначенных приоритетов, при равенстве — по номеру.
Сортировку можно поменять в списке или нажатием на заголовок «Приоритет».
Категория, статус и поиск применяются совместно. Число у категории показывает
количество задач с учётом текущего поиска и статуса; категории могут пересекаться.

Категории и приоритеты меняются редактированием JSON, страница их показывает.
Добавление категории: добавить запись в `categories` и её `id` в нужные задачи.
Удаление категории: сначала убрать её `id` из задач, оставив каждой хотя бы одну.
Скрытых копий метаданных в браузере или генерируемого списка внутри HTML нет.

При добавлении, переименовании, переносе в архив или удалении задачи обновлять
`index.json`, `BACKLOG.md` и соответствующий Markdown-файл. При взятии задачи
в работу установить `status: "in_progress"` в JSON и добавить `[В РАБОТЕ]`
к заголовку в старом индексе и подробном файле.
В индексе страницы только активные задачи; архив остаётся в `ARCHIVE/`.

Проверка целостности индекса и логики фильтров/сортировки, из корня проекта:

```powershell
node --test tools/test-backlog.cjs
```
